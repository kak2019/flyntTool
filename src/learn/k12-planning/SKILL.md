# 中国 K-12 课程设计

生成一套可直接使用的中国课堂材料：教师教学设计、学生学习单和课堂观察记录表；需要时增加素材页、实验记录单或任务卡。始终使用简体中文，除非教师明确要求双语材料。

## 0. 先路由，再提问

1. 判断学段：小学一至六年级；初中七至九年级；普通高中高一至高三。若教师明确使用五四学制，按其年级体系处理，不擅自换算。
2. 判断学科并立即读取对应参考：
   - 语文：`references/subject-chinese.md`
   - 数学：`references/subject-mathematics.md`
   - 英语：`references/subject-english.md`
   - 科学、物理、化学、生物学：`references/subject-science.md`
   - 道德与法治、思想政治、历史、地理：`references/subject-humanities.md`
   - 信息科技/信息技术、劳动、艺术、体育与健康：`references/subject-practice-arts.md`
   - 跨学科主题：同时读取涉及学科的参考，以一个真实成果统整，不把多学科内容简单拼盘。
3. 必须读取 `references/curriculum-grounding.md`
4. 识别教材信息：出版社/版本、年级、上下册、单元、课题。教师明确教材时保持其单元逻辑；未明确时不得猜测“人教版”。

## 1. 澄清最少但关键的信息

从上下文先推断，需要教师补充或选择时使用宿主提供的结构化用户输入工具（如 `request_user_input`、`AskUserQuestion` 或等价能力），不要直接发送开放式问题。一次交互最多呈现 2 个问题。优先级：

1. 年级或学段；
2. 学科与课题；
3. 教材版本、册次、单元位置；
4. 课型与课时；
5. 学情：已学内容、常见困难、班级差异；
6. 地区性要求：中高考题型、地方课程、校本模板。

交互式提问遵循：

- 每个问题提供 2–3 个互斥选项，把推荐项放在第一位并简述影响；
- 年级、课题、教材版本等无法穷举的事实，使用交互组件提供的“其他/自行输入”入口，不另发开放式追问；
- 能从上下文可靠推断的信息不再询问；不影响当前设计的信息采用默认值；
- 需要教师上传教材页或校本模板时，提供“现在上传”“按现有信息继续并标记待核对”“取消本次生成”等可执行选项；
- 宿主确实没有结构化输入能力时，才退化为单条 A/B/C 选项消息，不得改成连续开放式提问，并说明当前界面不支持点击选择。

默认值：

- 一课时按 40–45 分钟设计，高中或教师明确时按实际课时；
- 按国家课程标准进行素养导向设计；
- 使用常见教室条件，不假设昂贵设备或境外平台；
- 未提供教材页时按课标和主题设计原创内容，并标注“教材对应位置待教师核对”。

通过交互式选择确定交付路径：

- “直接生成完整 Word 材料（推荐）”；
- “先看教学设计一览，确认后生成”；
- “只生成聊天预览”。

若教师已明确交付方式，不重复询问。未选择时默认生成完整材料。

## 2. 建立课程依据

按 `references/curriculum-grounding.md` 的证据优先级执行：

1. 教师提供的课标原文、教材页、教师用书或学校要求；
2. 教育部现行课程方案与课程标准原文；
3. 经核实的国家/省级教学用书目录与教材信息；
4. 基于可靠知识的概括，并明确标记“待核对”。

课程依据至少记录：

- 文件名称与版本；
- 学段、学科；
- 核心素养维度；
- 课程内容主题、任务群、内容领域或学习主题；
- 学业要求或质量表现；
- 本课与教材单元的关系。

网络可用且教师要求精确对齐时，优先查教育部或中国政府网官方来源。无法核实时，使用概括而非伪造逐字引文。

## 3. 设计教学

遵循已加载学科参考，并同时满足：

- 从核心素养和单元目标反推本课目标，不把目标写成知识点清单；
- 区分“学习目标”“评价证据”“学习活动”，保持三者一致；
- 先激活或诊断已有经验，再经历核心学习任务，最后用新情境检验迁移；
- 至少有一个需要解释、论证、探究、创作或解决真实问题的任务；
- 给出具体可观察的学习表现和教师应对，不写“学生可能不理解”；
- 课时总分钟数等于各环节分钟数之和，并计入发放材料、讨论和收束；
- 学生材料只写学生需要看到的内容，不混入教学意图、答案或教师提示；
- 作业遵循减量提质：基础巩固、变式应用、开放迁移分层可选，不用机械题海。

## 4. 可选的教学设计一览

教师选择预览时，先完成课程依据和学科设计，再展示：

- 年级、学科、课题、教材位置；
- 课程依据概括；
- 2–3 条可评价学习目标；
- 环节、分钟、学习任务、评价证据；
- 学生实际要完成的核心任务；
- 课堂检测或出口任务；
- 对本班学情的关键适配。

展示一览后使用交互式确认：

- “确认并生成完整材料（推荐）”；
- “返回修改教学设计”；
- “只保留预览，暂不生成文件”。

## 5. 用单一内容源生成材料

读取 `references/document-schema.md`。创建一个 `lesson.json`：

- `shared`：年级、学段、学科、课时、教材信息、课程依据，以及所有跨文档复用的任务、材料、词汇和评价标准；
- `documents[]`：至少包含 `lesson_plan` 和 `observation_template`；有纸面学生任务时包含 `student_materials`；
- 用 `from_shared` 引用重复内容，不在不同文档中重写同一任务；
- 教师/学生表述不同时使用 `{teacher, student, stimulus}`；
- 所有学生作答任务后提供与任务量匹配的 `workspace`、`fill_table` 或其他作答载体。

教师教学设计建议包含：

1. 基本信息与课程依据；
2. 单元位置与学情分析；
3. 核心素养导向目标；
4. 重点、难点及其依据；
5. 评价任务与成功标准；
6. 教学过程（学习任务、教师支持、学生表现、评价证据、时间）；
7. 板书设计；
8. 作业与课后反思观察点；
9. 可调整项与不可轻易削弱的设计。

先运行结构验证：

```bash
python scripts/validate_material_source.py lesson.json --mode planning
```

通过后运行：

```bash
bash scripts/render_all.sh lesson.json "$OUTPUT_DIR"
```

无 Bash 的 Windows 环境直接运行：

```powershell
python scripts/render_documents.py lesson.json --format both --outdir <输出目录>
```

检查每个 `documents[].id` 都生成 `.docx` 与 `.html`，且文件非空。只向教师交付 Word 文档；HTML 和 JSON 留作预览与后续修订。

## 6. 交付与修订

交付时：

1. 用教师语言概括产物，不提 JSON、脚本、schema 或渲染；
2. 说明哪些课程依据已核实，哪些教材位置需要教师确认；
3. 使用交互式选择收集交付反馈，不直接开放式追问；
4. 提供“满意并结束”和 2–3 个与本课高度相关的迭代选项，如压缩为 40 分钟、匹配指定教材页、加入中考/高考型迁移、针对学困点补充支架。

修订时只改 `lesson.json` 后整套重渲染。共享任务在 `shared` 中修改；改数字、情境或文本后，检查所有文档是否仍残留旧内容。不得直接编辑生成的 Word 文件。

## 版权与安全

- 原创编写学生任务和教师话术；教材只用于定位、范围和教学逻辑。
- 不大段复制教材、教参、试卷或受版权保护文本；必要时请教师提供已获授权的课堂材料。
- 语文引用古诗文、公版作品或法规原文时标明出处；现代作品只给必要短引和书目信息。
- 不生成歧视、羞辱、静态贴标签的分组语言；不公开学生隐私数据。
